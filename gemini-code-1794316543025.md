# Full Codebase & Agent Harness Audit Workflow

You are conducting a comprehensive, production-safe 4-phase audit of this repository. This product serves live users: do not cut corners, do not guess on ambiguous behavior, and never break existing functionality.

---

## 0. Pre-Flight Baseline & Global Execution Rules

Before touching any file:
1. **Check Working Tree:** Verify `git status` is clean so audit commits do not mix with uncommitted work.
2. **Establish Baseline:** Detect and run the project's existing test suite, typechecker, and linter to confirm the starting state passes.

Apply these three rules across every phase below:
- **Rule 1 — Verify Every Change:** Re-run relevant tests, typechecks, and linters after *every* modification. If a change fails verification, revert it immediately.
- **Rule 2 — One Atomic Commit Per Safe Fix:** Only auto-apply changes you are 100% confident are safe, deterministic, and behavior-preserving. Apply them one at a time and create a separate commit for each fix using the format:
  `audit(<phase>): <what changed> — <why it was needed>`
  Never batch unrelated fixes into a single diff; every fix must be cheap to inspect and revert independently via `git revert <sha>`.
- **Rule 3 — Strict Review Gate for High-Risk Changes:** Do NOT modify code for challenged architectural assumptions, core business logic, public APIs/schemas, cross-cutting state refactors, or security/permission configurations. Log those items with exact `file:line` references in the final **Audit Review Backlog**.

---

## Phase 1: Simplify & Cut the Superfluous
*(Priority Hierarchy: Delete > Simplify > Optimize > Automate)*

Audit the codebase for unnecessary code, over-engineering, and weak assumptions. Challenge how things are currently built before spending effort fixing or polishing code that should not exist.

1. **What can be deleted entirely?**
   - Identify dead code, unused exports, orphaned files, redundant abstractions, duplicate utilities, and unused dependencies.
2. **What can be simplified once the bloat is gone?**
   - Identify over-engineered wrappers, premature generalizations, unnecessary indirection, and complex logic that can collapse into simpler primitives.
3. **Challenge weak assumptions:**
   - Question legacy workarounds, defensive checks for impossible conditions, or over-complicated setups.
- **Action:** Remove 100% verifiable dead code and apply isolated, behavior-preserving simplifications via individual atomic commits (`audit(simplify): ...`). Hold any deletion or simplification that touches live customer behavior, external contracts, or contested assumptions for the Review Backlog.

---

## Phase 2: Full Codebase Health Check

Read the remaining codebase and find everything that is broken, inconsistent, inefficient, or no longer needed.

1. **Broken:** Latent bugs, unhandled errors/promises, broken imports, off-by-one errors, null/undefined hazards, race conditions, or resource leaks.
2. **Inconsistent:** Naming drift, mixed error-handling patterns, divergent folder/module conventions, or mismatched types and schemas.
3. **Inefficient:** Redundant computations, N+1 queries, unnecessary re-renders/allocations, blocking I/O on hot paths, or suboptimal data structures.
4. **Obsolete:** Stale feature flags, deprecated API usage, outdated comments/docs that contradict the code, or leftover migration shims.
- **Action:** Fix what you are 100% sure about via individual atomic commits (`audit(health): ...`) and list the rest with `file:line` references and concrete recommendations for review.

## Phase 3: Surface Implicit State Machines
*(Fewer Words, Big Visuals — Optimizing UX, DX, and AX)*

Audit the codebase for implicit state machines—tangled boolean flags (`isLoading`, `isError`, `isSuccess`), scattered status strings, or deeply nested `if/else` transitions—that would drive concrete improvements if made explicit:
- **UX (User Experience):** Eliminate impossible UI/system states, stuck loading states, and unhandled edge-case transitions.
- **DX (Developer Experience):** Make valid states, events, and transitions self-documenting and type-safe.
- **AX (Agent Experience):** Make state flows deterministic and local so AI agents can reason about and modify behavior without breaking hidden couplings.

For each implicit state machine found:
1. **Visualize First (Fewer Words, Big Visuals):** Draw a Mermaid `stateDiagram-v2` showing the current implicit states, transitions, and any unhandled, dead-end, or impossible states.
2. **Evaluate & Triage:** Rank candidates by combined UX/DX/AX impact.
3. **Action:** For isolated, self-contained state machines where refactoring is 100% behavior-preserving, refactor them into explicit state machines (e.g., discriminated unions, transition tables, or state reducer patterns) one at a time via atomic commits (`audit(state): ...`). For complex or cross-cutting flows, output only the Mermaid diagram and proposed explicit transition design in the Review Backlog without touching the code.

## Phase 4: Audit Agent Configuration & Harness (Harness-Agnostic)

Discover and review all AI agent configuration and harness files in the repository (such as `AGENTS.md`, root/directory rule files, skills, workflows/commands, subagent/role definitions, lifecycle hooks, sandbox/permission settings, and MCP/tool server configs) against current frontier-model best practices:

1. **Context & Attention Economy (Always-On vs. On-Demand):**
   - Check whether always-on root instruction files (`AGENTS.md`, global system rules) are lean (<200 lines) and strictly reserved for universal repository facts, build/test commands, and global negative constraints.
   - Flag task-specific playbooks, verbose reference material, or domain-specific rules bloating always-on context that should be extracted into on-demand skills, lazy-loaded workflows, or path-scoped rules.
   - Identify duplicate, stale, or contradictory instructions across different agent config files.
2. **Deterministic vs. Advisory Guardrails:**
   - Identify critical rules written only as advisory prose (e.g., secret protection, forbidden directories, formatting, mandatory test/lint checks) that *must* hold 100% of the time.
   - Propose deterministic enforcement mechanisms (agent lifecycle pre/post hooks, git hooks, or CI/linter gates) to replace fragile prompt-only guardrails.
3. **Least Privilege, Subagents & Tool/MCP Hygiene:**
   - Check subagent or specialized role definitions for bloated prompts, overlapping triggers, or overly broad tool/shell access on read-only or research tasks.
   - Audit command allowlists/denylists, sandbox permissions, and MCP server configurations for over-permissioned write/delete/network access, unpinned external packages, or excessive tool-schema token overhead.
- **Action:** Apply safe, non-destructive cleanups (deduplicating prose, fixing broken file paths in docs, tightening skill/rule trigger descriptions) via individual atomic commits (`audit(harness): ...`). Do NOT auto-modify security permissions, hooks, subagent tool scopes, or MCP configs—list them in the Review Backlog for approval.
